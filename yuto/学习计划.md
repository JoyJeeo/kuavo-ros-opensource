# Kuavo ROS 代码仓深入学习计划

## 1. 学习目标

本计划的目标不是简单浏览目录或记住 ROS topic，而是建立对 Kuavo 机器人软件系统的完整理解。完成学习后，应当能够：

1. 从外部控制命令出发，解释命令如何经过 ROS、目标轨迹、MPC、状态估计和 WBC，最终形成关节控制命令。
2. 从传感器输入反向追踪机器人状态如何被估计、转换并反馈给规划和控制模块。
3. 理解机器人版本、模型、质量、关节数量、电机类型和末端执行器配置对系统的影响。
4. 区分实机、MuJoCo、Gazebo 和 Isaac Sim 后端，理解它们与控制核心之间的边界。
5. 理解 Python SDK、ROS API、遥控器、VR、IK 和业务案例如何复用底层控制能力。
6. 理解数据挑战赛的场景随机化、任务生命周期、动作接口和评分逻辑。
7. 面对运行异常时，能够判断问题属于命令、模型、MPC、估计、WBC、硬件、仿真还是业务层。
8. 能够向其他开发者清晰讲解仓库的架构、核心数据流和关键设计决策。

最终验收标准是能够独立回答：

- 为什么机器人没有站起来？
- `/sensors_data_raw` 正常但 `/joint_cmd` 异常时，应当检查哪些模块？
- MPC 正常运行但机器人仍然摔倒时，如何区分模型、估计、WBC 和硬件问题？
- `/cmd_vel`、`/cmd_pose` 和 `/cmd_pose_world` 的控制链有什么区别？
- 手臂外部轨迹为什么需要切换控制模式？
- 为什么修改机器人质量或模型后需要处理 CppAD 缓存？
- 如何将控制后端从 MuJoCo 替换为 Gazebo、Isaac Sim 或实机？
- 如何在 Python SDK 中增加一种新的机器人能力？
- 如何区分挑战赛策略失败、控制失败和场景/评估器失败？

## 3. 重要源码边界

以下核心模块没有完整源码位于 `src/`，而是通过 `installed/` 中的头文件和预编译库提供：

- `humanoid_interface`
- `humanoid_wbc`
- `humanoid_estimation`
- `humanoid_interface_drake`
- `hardware_node`
- `hardware_plant`

学习这些模块时采用以下方式：

1. 阅读公开头文件，理解类职责和调用契约。
2. 阅读调用方，确认输入、输出和生命周期。
3. 阅读配置文件，推断任务、约束和算法参数。
4. 通过 ROS topic、日志和运行行为验证理解。
5. 明确区分“由源码确认的事实”和“由接口与行为推断的结论”。

不要因为缺少实现源码而跳过这些模块，也不要假设头文件中未体现的内部行为。

## 5. 学习方法

每个阶段统一采用以下五步，避免无目标地连续阅读文件：

1. **读接口**：识别类、节点、topic、service、配置字段和数据类型。
2. **画数据流**：记录模块输入、处理过程、输出和下游消费者。
3. **追踪实例**：选择一个实际命令，从入口一路追踪到最终输出。
4. **分析失败路径**：记录超时、数据非法、模式不匹配和安全检查失败时的行为。
5. **复述与验收**：脱离代码讲解模块，并回答阶段验收问题。

每个模块的学习笔记固定包含：

- 模块职责
- 输入和输出
- 核心数据结构
- 内部状态和状态迁移
- 配置来源
- 线程、频率和生命周期
- 单位、坐标系和数组顺序
- 异常和保护路径
- 可观测的 ROS topic、service 和日志
- 一个完整调用实例
- 尚未确认的问题

### 17.3 核心问题

### 17.4 故障定位框架

按以下顺序缩小范围：

1. 启动层：节点、参数、环境变量和模型文件是否存在。
2. 输入层：命令 topic/service 是否收到正确数据。
3. 估计层：姿态、速度、接触和关节状态是否合理。
4. MPC 层：目标、步态和 policy 是否持续更新。
5. WBC 层：加速度、接触力和扭矩是否有限且连续。
6. 输出层：`/joint_cmd` 的维度、模式和数值是否正确。
7. 后端层：仿真或硬件是否正确消费命令并反馈传感器。
8. 业务层：状态机、超时和成功判定是否正确。

### 17.5 验收标准

面对一个具体现象，能够提出按优先级排列的检查清单，并为每一步指定可观察的 topic、日志或配置。

## 19. 后续教学方式

后续由教学导师按阶段推进，每次只处理一个清晰主题。每节课应包含：

1. 本节目标和前置知识。
2. 架构位置与上下游关系。
3. 关键源码逐段讲解。
4. 核心数据结构和单位说明。
5. 一条完整调用链演示。
6. 常见误区和故障表现。
7. 课堂提问与理解检查。
8. 一个不修改仓库源码的阅读或分析练习。
9. 本节总结和下一节衔接。

教学过程中应遵循：

- 先解释业务目的，再讲实现细节。
- 先读调用关系，再深入算法。
- 明确指出源码事实、合理推断和未知边界。
- 不用术语替代解释。
- 对状态向量、数组和配置始终标注维度、顺序与单位。
- 每学完一层，都能回到完整控制链中说明它的位置。
- 未通过当前阶段验收前，不盲目进入下一阶段。
